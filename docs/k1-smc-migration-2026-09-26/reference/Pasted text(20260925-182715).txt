1. What this lane is

The assignment was SMC-TITAN-CONTROL-001: give you immediate physical control of the running Titan visual pipeline from the owned M-VAVE SMC-Mixer, through macOS CoreMIDI, with the Mac carrying parameters and Titan keeping audio, rendering and LEDs.

It is a new host-side sub-lane in SMC-Mixer. It is not the historical ESP32 controller, not Blender, not K1.Sliders, and not a restart of the solved BLE/USB-MIDI connection work.

A meaningful result, per the brief, is: move a physical control, see an acknowledged change in the intended live visual parameter, without resetting the effect or the audio pipeline, then save/reproduce the setting. That physical result has not happened yet. What exists is the host protocol path plus a Titan PATCH codec, proven offline.

4. The load-bearing Titan defect this lane is built around

On inspected 8427fcc, the existing whole-config setter (opcode 25 BEGIN/APPEND/COMMIT or SET_CONFIG) does this in live_apply_config():

• calls PaletteRuntime::configure(), which resets runtime state (timing, dwell, live-audio wait, visual path)
• forces live_cfg.emit_on = 1
• forces palette flags with emit bit on ((cfg.flags | 4) & ~2)

So driving that setter at fader rate would reset the scene and fight emission authority. The new path is a PATCH subcommand that copies visual scalars onto the live channels and leaves emission, modes, palettes and AP/VP timing alone.

5.1 Contract

docs/contracts/titan-live-v1.json now includes:

• config_subcommands.PATCH = 8
• patch object: max 8 entries, 12-byte header, 8-byte entries, kind_f32 = 1
• explicit flags: does not call palette configure; does not change emission authority

k1_live_schema.inc regenerated from that JSON. Current schema SHA-256:

05198c7a0ad56c06a9ed29b13c8845a8a10da90d3dbff0f68098d2aa5d70f817

5.2 Wire format (opcode 25, subcommand 8)

u32 expected_revision
u32 request_id
u16 count
u16 logical_channel   # 0 = visual_a, 1 = visual_b
then count × { u16 field_id, u16 kind, f32 value }

All-or-nothing: unknown field, duplicate field, NaN, out-of-range, wrong kind, or stale revision rejects the whole patch. On success, revision increments by 1. emit_on, flags, mode_*, palette_* are copied through unchanged.

7. Challenges and blockers discovered

1. The full brief was not in the repo.
The dispatch pointed at SMC-TITAN-CONTROL-001.md. The file was in ~/Downloads/. First implementation used a plausible eight-fader map (hue on fader 1, bloom/incandescent as extras). After the brief was found, that map was torn out and replaced with the specified roles, and first path moved to fader 6 / hue. Cost: a second protocol/profile pass in the same session.

2. Whole-config is unsafe at fader rate.
Confirmed in fixture_app.cpp on 8427fcc. PATCH exists because SET_CONFIG is the wrong tool.

3. Takeover unit mismatch.
Soft pickup compared physical 0–1 to acknowledged parameter units. Hue worked (both 0–1). Motion (shift_rate default 120) never engaged, because physical never reaches 120. Symptom: eight-control test got 7 of 8 applied. Fix: pickup compares requested vs acknowledged in parameter space.

4. Worktree placement conflict.
Dispatch proposed Software/.worktrees/…. Global rule: worktrees live inside the existing repo. Resolved by in-repo .worktrees/. Correct, but the dispatch path is now a documented deviation.

5. workflow_bind / registry.
No PLAN_TASKS.json. Verify receipts exist; there is no frozen case-verifier PASS for this ticket.

6. Hardware admission is a hard stop, not a missing test.
The brief and dispatch forbid CDC, programming, emission, LED probe without Captain admission and an identified candidate. Offline work proceeded. Live PATCH on silicon is NOT_TESTED, not failed.

7. fixture_app.cpp PATCH handler is uncompiled on target.
The codec is host-tested. The command-handler glue is source-reviewed only. An ARM live-runtime build from this branch has not been run.

8. Broker ownership vs campaign opcodes.
Observe broker today admits INFO/metrics/palette_status, campaign=False. Opcode 25 needs campaign mode. A naive “allow 25” would also allow SET_CONFIG. Restriction has to be subcommand inspection (PATCH only), which is why RestrictedControlPlane exists and why it is not yet the default broker loop.

9. Capture last-settled values are mostly zero.
Replay of fader 6 hue lands at 0.0 because that gesture ended at the bottom. That is a real settled value, easy to misread as “the write did nothing”.

10. TypeSafe was invoked and not used on the product path.
Fader mapping is capture-deterministic. Putting Jev on “is this CC an encoder?” would guess bindings the brief ordered left unbound.

8. Lessons

• Find the named brief before designing the map. Dispatch plus capture analysis is not a substitute for the full role table.
• The map is not the territory. Capture JSON, mido pitch, and wire bytes agreed here; LSB-nonzero is an explicit error because the admitted profile never saw it.
• Pickup must live in the units you write. Physical 0–1 vs shift_rate 0–240 is a silent seven-of-eight bug.
• configure() is not a parameter setter. It is a scene reset. Partial visual copy is the fader-rate primitive.
• Identical MIDI on three ports is a duplication hazard, not three independent streams. Production is one name: Master.
• A green in-process ACK is the protocol. Plate motion is a later, admitted, identity-bound measurement.
• Sibling worktree paths in a dispatch are proposals. In-repo .worktrees/ is the live rule.

11. What I believe should be done next

Order matters. Do not flash to “try the faders”.

Already in source: host adapter, capture tests, PATCH codec, restricted IPC, fixture handler, admission hold.

Remaining, numbered:

1. You admit a live candidate (identity/build) and that this branch may open CDC. Without that, hardware stays held.
2. Build the live-runtime image from feat/titan-live-control-001 (schema must match 05198c7a…). Confirm k1_live_schema.inc pin in the build receipt.
3. Programme that image through the existing RA8P1 E2 Lite path (not this session; not serial ROM). Programming success is bytes-on-target, not “PATCH works”.
4. Run one CDC owner — Titan broker with RestrictedControlPlane, campaign transport, PATCH and GET_CONFIG only, no SET_CONFIG. Unix socket, user-only permissions.
5. Host live replay against that broker (still can start from the capture file, then from Master). Prove GET_CONFIG visual_a.hue_position tracks fader 6, emit_on unchanged, no configure() side effects (no blackout, no mode cut, no audio restart).
6. Then enable the other seven faders on the same candidate. Intensity stays clamped to the admitted ceiling.
7. Then snapshot save/recall, labelled learning for encoders/buttons, UI process.

Shipped means: on the admitted candidate, GET_CONFIG/hue_position follows fader 6, emission unchanged, scene not reset. A simulated ACK does not count.

Until step 1, the useful continuation is still offline: wire the broker loop, unix socket, live ingress behind a flag, snapshot file format, and an ARM compile of the fixture PATCH arm without flashing.
